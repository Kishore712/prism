## Observable outcome and acceptance

1. A fresh collaborator agent reads the synthetic pilot package, repairs its script, actually cleans and calculates the data, inspects outputs, writes a qualified report, and returns an immutable package. No operator supplies the analytical solution or repairs generated code. Independent scoring checks cleaning counts, segment and standardized arithmetic, seeded bootstrap intervals, source preservation, review-pending language and actual run/artifact references.
2. In the same conversation, a new target population causes a new exact-input computation and return. The first artifact remains byte-identical. Queries about completed results cause no execution; missing population weights cause clarification without edits, jobs or access requests.
3. The model cannot acquire Python permission from an old grant, change runtime limits, execute unselected code, bypass revision/revocation checks, or perform side effects during final-answer correction. Relevant deterministic denials precede live acceptance.

## Implementation decisions

Keep the existing PydanticAI agent and OpenAI Responses adapter. Add typed scoped computation/result tools backed by the existing Jobs/worker development runtime; no generic terminal, network, dependency installer or framework migration. Owner selection can explicitly narrow runtime input files while keeping a report shared with the conversational agent. This prevents a report-only edit from invalidating computation whose executable input set excludes that report. Existing Python policies continue to stage every non-output selected file and do not acquire new rights.

Only Python-enabled Continue sessions use a larger finite agent envelope: 16 model requests, 24 tool calls, 180 seconds, 6,000 output tokens per response and 128 KiB serialized request bodies. Retain the previous limits for other sessions and reserve final-answer/correction requests without side-effect tools. This is application orchestration, separate from the unchanged 30-second/1-CPU/256-MiB task runtime. The aggregate application cost cap remains disabled by explicit owner choice, with the original ledger retained. Reservations are estimates, not invoices.

Real model, runtime, browser and scripted-model evidence must be labeled separately. Preserve failed attempts and record actual tokens, timings and owner interventions. A synthetic milestone pass does not establish general reliability, mathematical validity for other studies or broad security assurance.
