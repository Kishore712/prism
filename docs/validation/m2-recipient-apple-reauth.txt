Date: 2026-09-22

This sanitized record summarizes the latest approved Apple Connect

## Result

- Guest recovery post-login validation passed: backend `Running`, server
  `Online`, and exact existing hostname, tag, unsafe preferences, and

- The run then intentionally failed with `old_admin_identity_reused` because

- Apple tailnet control-plane state shows exactly two nodes: `prism-client` and
  one `prism-pilot`. There is no duplicate pilot node. The existing pilot host

## Interpretation and remaining evidence

The guest reauthorized the same stable identity already represented by the
existing host node. The current script assumes reauthorization must produce a
new identity and rejects a matching saved identity hash. This result therefore
shows that the script's new-identity assumption was not met; it is not evidence
that the stable identity is unsafe. The duplicate-node guard worked: the
existing two-node state was preserved.

Passive reboot persistence has not yet been checked after this reauthorization.
Exact private DNS resolution and reachability also remain pending. Earlier
diagnostics and the fresh 33/33 Kata baseline remain separate evidence.
