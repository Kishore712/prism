# Synthetic pilot analysis requirements

All identifiers and revenue units are synthetic. Nothing authorizes publication, rollout or deployment. Approval stays pending.

Remove exact duplicate rows; reject missing user IDs with a reason. Conflicting rows for one user must block analysis. Use all eligible users as denominators. Compare conversion and revenue per user overall and within each segment, then standardize with analysis-plan.json weights. Distinguish percentage points from relative change and composition effects from causal evidence.

For the complete analysis, estimate uncertainty for the same plan-weighted standardized B-minus-A conversion and revenue-per-user differences as the point estimates; apply the plan weights inside every bootstrap replicate (not the observed variant composition). Sample with replacement within each variant/segment retaining stratum sizes, in order A/new, A/returning, B/new, B/returning. Sort each stratum by user_id; choose each sampled index with rng.randrange(len(stratum)). Use random.Random(17), 2,000 replicates, conversion before revenue (the same sampled users for both). For the 95% percentile interval sort all differences and linearly interpolate at index (n-1)*p for p=.025 and .975. Report assumptions and finite-resample limitations.

Write only results/metrics.json and results/data-quality.json as deliverable numerical outputs. The report needs human review. Runtime completion alone does not verify methodology. The supplied script is intentionally an incomplete raw comparison for a later agent repair task.

## Numerical deliverable contract

Use this explicit JSON shape so a reviewer can check the complete comparison, not just differences. In `results/metrics.json`, include `overall` with A/B objects and `segments` with new/returning objects containing A/B objects; every observed group object has `users`, `conversions`, `revenue`, `conversion_rate`, and `revenue_per_user`. Include `target_weights`, `standardized` A/B objects with `conversion_rate` and `revenue_per_user`, and `difference` with those same two keys for standardized B-minus-A. Include `bootstrap` with `seed`, `replicates`, and `interval_95` containing `conversion_rate` and `revenue_per_user` endpoint arrays for that same standardized difference.

In `results/data-quality.json`, include `raw_rows`, `exact_duplicates_removed`, `missing_id_rows`, `eligible_users`, `conflicting_user_ids`, `rejection_reasons`, and `conservation_check`. Duplicate count means excess exact rows removed, not all members of duplicate pairs and not a second pass over an already deduplicated collection. Require raw_rows = exact_duplicates_removed + missing_id_rows + eligible_users on a non-conflicting dataset. Conflicts must exit nonzero before writing numerical deliverables. The report must discuss overall versus standardized estimates, segment composition, percentage points versus relative change, intervals, assumptions and pending human review. Do not hard-code the fixture's counts or estimates.
